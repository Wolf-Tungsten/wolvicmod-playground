## 1. 问题

三个需求：

1. **任意组合的复合类型**：`Vec`（同质聚合：元素类型均匀、长度运行期）与 `Bundle`（异质聚合：命名字段、类型各异）可以互相嵌套成更复杂的类型——Vec of Bundle、Bundle of Vec of Bundle……
2. **粒度驱动**：复合类型的 WIRE/REG（及端口）既可**整体赋值**，也可**按字段/元素粒度赋值**——`dc.valid = x`、`v[0].A = y`，且两种形态可以在同一实体上按叶子混用。
3. **与任意 C++ 类型协同**：宿主类型（`std::deque`、用户类等）是行为表达力的来源——整体访问、不可综合，但与可综合族在同一套实体骨架上共存，两侧的值要能机械地来往。

难点在于与框架既有机制的相容性：SSA（每个信号恰一条驱动）、脏驱动调度（依赖追踪要精确到叶子——`valid` 变化不应唤醒只读 `payload` 的动作）、波形与诊断的叶子路径命名。粒度驱动若做不干净，这些机制每个都得为复合类型写一套特判。

## 2. 类型体系总览：两个族

| 族 | 类型 | 实体形态 | 可用位置 |
|---|---|---|---|
| **可综合族** | `Bool` / `UInt` / `SInt`（叶子标量）、`Vec` / `Bundle`（复合节点） | 叶子展开（§3） | `cmodel()` 与 `rtl()` 皆可 |
| **宿主类型** | 任意 C++ 类型（`std::vector`、用户类等） | 不透明单实体（§4） | 仅 `cmodel()` |

**可综合性是类型的属性**，判据两条：形状在冻结时确定（位宽 / 长度 / 字段树全部定型）；运算在白名单内（`UInt`/`SInt` 类型库的 API 面，RTL 规划 §2）。两个族共享同一套实体骨架——Wire/Reg/Mem/In/Out、Assign/Update、读集与注册链——类型只决定三件事：实体是否展开为叶子、`rtl()` 里能用哪些操作、模块能否进入可综合世界。

每个实体有两副面孔，先立清概念再谈规则：

- **结构视图**：实体树的节点句柄——用于驱动（赋值目标）、命名、波形；
- **值视图**：动作 lambda 经读集拿到的值——用于计算。

## 3. 叶子展开：可综合族的实体树模型

复合类型的实体在声明时**展开为叶子实体树**：

- 叶子是 `Bool` / `UInt` / `SInt` 标量实体；`Vec` / `Bundle` 是内部节点——**视图而非存储**，自身不持有仿真值；
- SSA、依赖追踪、优先级链、波形、Verilog 映射全部在叶子级原样运行；框架核心只新增"可展开实体"一个概念，结构检查（多驱动、悬空）照旧作用于叶子；
- 叶子命名自动派生：`dc.valid`、`v[0].A`，照常注册命名表、照常拼层次路径。

**展开时机**：样品定型即展开——内部实体在创建时展开（样品已完整）；端口在构造函数返回、冻结对账时展开（`Vec` 长度、`UInt` 位宽可能此刻才补齐，见框架规划 §2.3）。无论哪条路径，展开都先于建模函数运行，建模函数拿到的叶子句柄是现成的。

宿主类型不展开：它是不透明的单实体（§4），自身即叶子。

## 4. 宿主类型：不透明整体

宿主类型是**任意 C++ 类型**——`std::vector`、`std::deque`、用户自定义类。它们是行为侧表达力的根基，规则刻意简单：

- **整体驱动**：不透明单实体，不展开、不可粒度驱动；SSA 在实体级（恰一条 Assign），Update 为整体次态替换（Mem 仍按行提交——行类型可以是宿主类型）；
- **读**：`reads(x)` 给出整体值的 const 引用；依赖粒度 = 整个值——任何字段变化唤醒全部读者。粗，但行为侧的正确性不依赖细粒度（黑盒 lambda 本就自己管理内部访问），性能损失是行为侧的合理代价；
- **变化检测**：类型有 `operator==` 则按值检测（不变不脏，下游不唤醒），否则恒脏——沿用 Wolvicmod 的既有策略；
- **波形**：默认不出现在波形中（静默跳过）；用户类型可特化 `FstFormat<T>` 整捆编码为位向量（Wolvicmod 框架规划 §6.3）；
- **出现位置**：`cmodel()` 的内部实体任意使用；端口仅纯行为模块可用（接口规则见 §5）；`rtl()` 永不出现。

宿主类型不进复合：`Vec` 的元素、`Bundle` 的字段必须是可综合族——叶子展开要求形状确定，宿主类型无形状可言。行为侧需要混合聚合时，用宿主容器（`std::vector<MyStruct>`）作不透明实体，而不是往 Bundle 里塞宿主字段。

## 5. 两族协同：边界与转换

两个族在同一个模型里共存，值在边界上机械来往。规则：

- **边界即端口**：双模模块的端口类型必须可综合族——同一组端口值要在行为树、可综合树、Verilated 模型之间机械传递（接口规则，框架规划 §2.4）；纯行为模块（含双树共同根以上的 testbench 世界）的端口任意；
- **转换发生在 lambda 读写信号的地方**，不设隐式中间层：
  - 读：`cmodel()` 的 lambda 读到 `UInt` 值，显式转宿主值参与任意 C++ 计算（如 `uint32_t(d)`）；
  - 写：驱动点把 lambda 返回的宿主值转入目标类型——值须位宽可容，创建/记录期检查，报错附层次路径；
  - 原生整型端口沿用存储兼容条款（RTL 规划 §2）：`bool`、`uint8_t`…`uint64_t` 与位向量一一对应；但参与生成 RTL 的运算必须经 `UInt`/`SInt`；
- **两棵树各用各的族**：行为树节点的内部可以是宿主类型（Queue 行为侧的 `std::deque`），可综合树节点的内部全是可综合族；两棵树之间机械传递的只有共享端口的值——这是对拍成立的物质基础；
- **observe 的摘要类型是宿主类型**：可比对、可打印即可，无需可综合——摘要 lambda 本就生活在一侧黑盒里，不参与生成；Verilated 侧经信号组成员的原样引出获取原料（RTL 规划 §4.2）。

## 6. 粒度驱动规则

### 6.1 静态路径

字段名与常量下标构成**结构路径**，在声明期（建模函数执行中）解析为叶子或子树句柄：

```cpp
dc.valid = en && !full;              // 驱动单个叶子
v[0].A   = expr;                     // 常量下标 + 字段：子树/叶子句柄
dout     = sr.payload;               // 叶子到端口
```

句柄的类型就是对应叶子/子树的实体类型——之后的 `.assign()` / `.update()` / `.reads()` / 快速路径与标量实体完全同用，注册链无需任何新写法。

### 6.2 叶子级 SSA 与缺口检测

- **每个叶子恰有一条驱动**：叶子要么被自己的路径驱动，要么被某个祖先节点的整体驱动覆盖；两者同时存在 = 多驱动，elaborate 报错；
- **只驱动部分字段**：其余叶子悬空，elaborate 报错附叶子路径（`'top.dc.ready' is never driven`）——粒度驱动不会削弱结构检查，反而把它精确到了叶子。

### 6.3 整体驱动 = 多目标动作

`dc = whole;`（以及 `cmodel()` 侧的 lambda 形式 `dc.assign().reads(...) = ...`）注册为**一个动作、驱动全部叶子**：只求值一次，结果按叶子切片提交；叶子级的变化检测照旧逐叶进行，下游脏传播依然精确。

两种整体形态在依赖精度上有差异，写明在明处：

- **lambda 整体驱动**：读集是整体的——黑盒无法分解，任一源叶子变化都会唤醒它；
- **表达式快速路径**（`dc = a`、`dc = mux(c, a, b)` 等可逐叶提升的白名单表达式）：表达式树静态可分解到叶子，依赖自动精确。

写法对照（两侧形态之别，见框架规划 §2.4/§2.5）：

```cpp
// cmodel()：lambda 整体驱动——一次求值，按叶切片提交（多目标动作）
dc.assign().reads(en, full, data) = [](auto src) {
    auto [en, full, data] = src;
    Decoupled v;                     // Bundle 类兼任样品与值两种角色（与 UInt 同）
    v.valid = en && !full;           // 字段就是普通成员赋值
    v.payload = data;
    return v;                        // 返回聚合值
};

// rtl()：没有 lambda——逐叶表达式，或经局部记录临时量整体连接
dc.valid   = en && !full;
dc.payload = data;
// 或：
Decoupled v;                         // 局部记录临时量：字段即表达式槽
v.valid  = en && !full;
v.payload = data;
dc       = v;                        // 整体连接，逐叶展开
```

聚合值构造的规则（两侧一致）：

- **字段宽度随写入值确定**——`v.payload = data` 取 `data` 的位宽；赋值时与目标叶子位宽对账，不一致报错附层次路径；
- **字段必须写齐**——漏写 `ready` 在记录/提交期报错（`aggregate value for 'top.dc' never assigns field 'ready'`），否则那片叶子拿到垃圾；
- Reg 整体 Update 同形：聚合次态一次求值、按叶切片进各叶子的优先级链（§6.4）。

`reads` 粒度同理可选：`reads(dc)` 依赖全部叶子；`reads(dc.valid)` 精确到叶子——依赖精度由建模者按取值需要控制。

#### 整体驱动在 rtl() 的成立条件：可逐叶分解

`rtl()` 的建模体里没有 lambda——每条连接/表达式语句在记录期直接产生表达式 DAG，逐叶精确，切片是平凡操作。成立的全部前提收敛为一条：**白名单只收可逐叶提升的操作**。两条纪律：

- 聚合操作只收**可逐叶提升**的——恒等、`mux`、逐字段/逐元素运算、`cat`/`rep`/切片、值级动态下标写（`nv[i] = x` 分解为逐元素 `mux(i==k, x, v[k])`）。任何不可分解的聚合操作（整体排序之类）永远进不了白名单；
- 三条形态约束（数据分支只走 `mux`、循环静态有界、函数调用自由）保证的正是可分解性：记录期正常选边、正常展开、正常内联，每片叶子都拿到独立的表达式。

`cmodel()` 的整体 lambda 才是真正的黑盒——但它不参与生成；粗粒度依赖（任一源叶子变化即唤醒）是行为侧声明过的代价，语义精确性不受影响。

### 6.4 Reg：叶子级 Update

叶子 Reg 是各自独立的状态：事件、使能、优先级链全部在叶子级——同一实体的不同字段可以有不同的更新条件：

```cpp
// rtl() 表达式形：
r.valid.update().on(posedge(clk)) = set || !clr;
r.payload.update().on(posedge(clk)).en(de) = din;

// cmodel() 的 lambda 形在同位置同构可用（.reads(...) = lambda）
```

**整体 Update**（`r.update().on(...)... = ` 聚合次态）展开为共享一次求值的叶子组：一次边沿检测、一次求值，意图按叶子切片，分别在每片叶子的优先级链中按注册顺序占位——叶子级混用整体与粒度更新时，优先级语义无歧义。

### 6.5 端口与层次

权限规则逐叶子继承：父模块可驱动直接子模块 `In` 的叶子（`sr.dc.valid = v;`）、读取 `Out` 的叶子；越级访问照旧禁止。复合端口的外部驱动（根模块 `set`/`get`）按聚合值进行。

## 7. 动态下标的二分

`v[i]` 的含义按下标性质二分——这是刻意的设计：

| 下标 | 解析结果 | 可读 | 可作驱动目标 |
|---|---|---|---|
| 建模期常量（字面量、循环变量、constexpr） | **结构路径** → 子树/叶子句柄 | ✓ | ✓ |
| 记录值（`UInt` 信号等） | **值表达式**（mux 树） | ✓ | ✗ |

- **动态下标的写目标被拒绝**：`v[i] = x`（`i` 动态）在 Wire 上语义不成立——Wire 无保持语义，"其余元素保持"在连续驱动下没有意义（隐式状态的构造性消除原则）。值表达式不提供赋值运算符，该写法在编译期失败；
- Reg 的元素条件更新是**值级操作**，rtl() 里用局部记录临时量写：

```cpp
auto nv = v;          // 局部记录临时量：复制当前值的表达式
nv[i] = x;            // 值级动态写 = 整向量的 mux 复合，白名单内
v.update().on(posedge(clk)) = nv;
```

- 大规模按地址寻址的写入仍属 `Mem` 的领地（整行粒度，§10）。

## 8. Vec 定义形态

Vec 与 Bundle 不同：字段开放所以 Bundle 需要用户定义类，元素均匀所以 **Vec 不需要用户定义——它是库提供的聚合模板**，元素类型是唯一的类型参数。

划分原则一句话：**类型的"是什么"进类型系统，"是多少"进运行期属性**。元素类型是值表示的一部分（`Vec<UInt>` 与 `Vec<Decoupled>` 是不同类型），编译期确定；长度与元素位宽只是数量，运行期可配。这与 `UInt` 去模板化并不矛盾，恰是同一条线的两端：位宽不进类型（所有 `UInt` 同构），元素类型必须进类型。

```cpp
Vec(UInt(8), 4)            // 样品：元素样品 + 长度；CTAD 推导出 Vec<UInt>，用户永不写尖括号
Vec(Decoupled(width), 4)   // Vec<Decoupled>：Vec of Bundle
Vec(Vec(UInt(8), 4), 2)    // Vec<Vec<UInt>>：Vec of Vec
```

推论与规则：

- **长度可缺省，元素类型不可缺省**——`Vec()` 形态不存在（成员声明处 C++ 类型必须确定）；`Vec(Bool())`（只缺长度）、`Vec(UInt())`（长度与元素位宽都缺）都合法；
- 缺省按属性独立，补全时给足完整样品，已定型属性须一致（重复定型报错）；对账递归到元素样品；
- 样品经 CTAD 书写；需要命名复用时取别名：`using Req8 = Vec<UInt>;`；
- Vec 的元素必须是可综合族（§4）；宿主聚合用宿主容器整体。

创建与补全：

```cpp
struct Mutex : Module {
    IN (Vec(Bool()),    req);        // 端口：长度缺省
    OUT(Vec(UInt(8), 4), rsp);       // 声明即完整

    explicit Mutex(int n) {
        req.setSpec(Vec(Bool(), n)); // 补齐长度；元素样品须一致
    }
};

void rtl() {
    WIRE(Vec(UInt(8), 4), v);        // 内部实体：创建即完整
    REG(Vec(UInt(), kMaxN), q);      // 元素位宽缺省 → q.setSpec(Vec(UInt(width_), kMaxN));
}
```

展开与访问（§3、§6、§7 规则的应用）：

- `WIRE(Vec(UInt(8), 4), v)` 展开为 4 个叶子 `v[0]..v[3]`（每片 `UInt(8)`）；Vec of Bundle 展开为 `rsps[0].valid` 这样的叶子路径；
- 结构路径 `v[0] = x`（常量下标驱动叶子）；整体 `v = whole`（多目标动作）；
- 值级：`reads(v)` 得 `Vec<UInt>` 聚合值；`v[i]` 动态下标读 = mux 树；值级动态写 `nv[i] = x`；
- **长度在记录期是常量**：`for (int i = 0; i < v.len(); ++i)` 的遍历在建模/生成期正常展开——长度创建后定型，白名单"循环静态有界"的约束天然满足。

#### Vec 作为端口：配置全流程

Vec 端口走"声明缺省 → 构造补齐 → 冻结对账 → 建模使用"的完整时间线（框架规划 §2.3）。声明与补全的组合（`OUT` 同理）：

| 场景 | 成员声明 | 构造函数补全 |
|---|---|---|
| 形状全固定 | `IN(Vec(UInt(8), 4), req);` | 无需动作 |
| 长度参数化 | `IN(Vec(Bool()), req);` | `req.setSpec(Vec(Bool(), n));` |
| 元素位宽参数化 | `IN(Vec(UInt(), 4), req);` | `req.setSpec(Vec(UInt(w), 4));` |
| 两者皆参数化 | `IN(Vec(UInt()), req);` | `req.setSpec(Vec(UInt(w), n));` |

规则：

- 补全给足完整样品；声明中已定型的属性在构造期可被覆盖（后写为准）——声明 `Vec(UInt(), 4)` 补 `Vec(UInt(8), 5)` 得到位宽 8、长度 5；
- 形状可从配置派生：`grant.setSpec(Vec(UInt(ceilLog2(n)), n));`；
- Vec of Bundle 端口同理：`IN(Vec(Decoupled(), 4), reqs)` 的字段位宽随完整样品递归补齐（`Vec(Decoupled(w), 4)`，机制见 §9 递归补全）；
- **各模块只配自己的端口**：子模块端口由子模块自己的构造函数补齐，父模块经 `MOD(Queue, q, 8, 12)` 透传构造参数而不越级代配——`MOD` 返回时子模块端口已定型、已展开；
- 冻结与展开先于建模函数：建模函数内叶子句柄（`req[i]`，常量下标）、整体句柄、`req.len()` 全部可用，逐叶子循环驱动正常展开：

```cpp
void rtl() {
    for (int i = 0; i < n_; ++i)        // n_ 是构造期配置，建模期常量
        gnt[i] = req[i] && grant_en;    // 逐叶子驱动；也可整体 gnt = ...
}
```

- 复合端口的外部驱动（根模块 `set`/`get`）按聚合值进行；Vec 值的构造形态待定（§11）。

## 9. Bundle 定义形态

Bundle 是框架感知的聚合类型，字段经 `FIELD` 宏声明（名字自动字符串化、注册进字段表）：

```cpp
struct Decoupled : Bundle {
    FIELD(Bool(), valid);
    FIELD(Bool(), ready);
    FIELD(UInt(), payload);              // 字段位宽可缺省

    Decoupled() = default;
    explicit Decoupled(int w) { payload.setWidth(w); }   // 样品树参数化：Bundle 构造与普通类无异
};
```

使用：

```cpp
WIRE(Decoupled(width), dc);     // 样品：构造参数直达字段位宽
IN(Decoupled(), dc);            // 或缺省：构造函数内 dc.setSpec(Decoupled(width))
```

**补全接口统一为 `setSpec`**：任何类型的实体都以提交完整样品树的方式补全——`UInt`、`Vec`、`Bundle` 同一形态；`setWidth(w)` 只是 `UInt`/`SInt` 的语法糖（≡ `setSpec(UInt(w))`）。

嵌套组合自然成立：`FIELD(Vec(Decoupled(), 4), rsps);`、`Vec(Bus(8), n)`。对账递归：构造函数返回时，样品树的每个叶子都必须定型。

#### 递归补全：Vec of Bundle 与嵌套样品树

补全 = 提交一棵**完整样品树**。`Vec(SomeBundle)` 端口的补全没有任何特殊性——Vec 层不感知元素字段，**参数化职责沿类型树逐层下沉**（每层构造函数各管各层）：

```cpp
struct Bus : Bundle {
    FIELD(Bool(),         valid);
    FIELD(UInt(),         addr);     // 字段位宽缺省
    FIELD(UInt(),         data);
    FIELD(Vec(UInt(), 2), lanes);    // 嵌套 Vec 字段：元素位宽缺省

    Bus() = default;
    Bus(int aw, int dw, int lw) {    // Bundle 自己管自己的字段
        addr.setWidth(aw);
        data.setWidth(dw);
        lanes.setSpec(Vec(UInt(lw), 2));
    }
};

struct Node : Module {
    IN(Vec(Bus(), 4), in);           // 只知道元素是 Bus、长度 4；字段细节不感知
    explicit Node(int aw, int dw, int lw) {
        in.setSpec(Vec(Bus(aw, dw, lw), 4));   // 一次提交完整样品树
    }
};
```

机制与规则：

- `setSpec` **平行遍历声明树与补丁树**：缺省处填入、已定型处**覆盖**（构造期允许覆盖，后写为准）、冻结时仍有缺叶子 = 对账报错附叶子路径；
- **默认值模式由此成立**：Bundle 的无参构造函数可以给字段默认值（`Bus() { addr.setWidth(32); }`），模块构造期覆盖——声明与默认构造给出的值是默认，构造期后写为准；
- 样品是普通对象，可以**先构造、再修改、再提交**——库提供的 Bundle 没有构造参数时的手工路径：

```cpp
auto b = Bus();
b.addr.setWidth(32);
b.data.setWidth(64);
in.setSpec(Vec(b, 4));
```

- 嵌套层级任意深：Node 不管 Bus 的字段，Bus 不管 lanes 的元素——每一层的参数化接口都是该层自己的构造函数。

#### 字段类型参数化：模板化 Bundle

字段的**类型**属于"是什么"——编译期决定，在 C++ 里就是模板。这不是回到模板体操：模板参数是**类型**，用于类型组合，而不是传数字——恰是"模板回归本职"的正面用法。

```cpp
template <Synthesizable T>                     // 字段必须可综合（§4），编译期约束
struct Timestamped : Bundle {
    FIELD(Bool(), valid);
    FIELD(UInt(),  ts);
    FIELD(T(),     payload);               // 字段类型由模板实参给定；属性仍可缺省

    Timestamped() = default;
    explicit Timestamped(const T& pl) {    // 通用参数化：配好的字段样品作构造参数传入
        payload.setSpec(pl);               // 样品是轻量描述物，const& 即可
    }
};
```

类型在模板实参处给定，属性沿样品机制补齐——两者正交，互不干扰：

```cpp
IN(Timestamped<UInt>(), p);                    // payload 是 UInt，位宽缺省
p.setSpec(Timestamped<UInt>(UInt(width_)));    // 补齐
WIRE(Vec(Timestamped<UInt>(UInt(8)), 4), ps);  // 与 Vec 组合：声明即完整
```

规则与边界：

- 模板化 Bundle 的每个实例化是不同类型——叶子展开形状各异，各走各的；
- `Synthesizable` 是框架提供的 concept（§11-10）：模板参数用它约束；`FIELD` 宏内部对字段类型 `static_assert` 同一约束——非模板 Bundle 的字段同样受管；
- `FIELD(T(), ...)` 要求 T 可默认构造；`Vec` 这类无默认构造的类型经 `Type<T>` 逃逸（框架规划 §7-6）；
- 对 T 有属性要求的构造函数写法用 `if constexpr` 兜住（`if constexpr (requires { payload.setWidth(w); })`）——但优先用上面的"字段样品作构造参数"写法；
- 运行期"字段类型可变"不是模板能表达的——那是带标签联合，用 Bundle 显式建模（`tag` 字段 + 各变体字段），或日后议专用 `Variant` 类型（§11）。

## 10. 边界与分工

- **cmodel 同享粒度机制**：叶子展开与粒度驱动是结构特性而非白名单特性——`cmodel()` 里使用可综合族类型时写法一致；
- **宿主类型不透明**（§4）：粒度机制只属于可综合族；`REG(std::array<int,4>, arr)` 在 cmodel 里仍是整体驱动的不透明值；
- **Mem 保持整行粒度**：行类型两族皆可（行为侧宿主行、可综合侧 `UInt` 行），行内字段访问是值级操作；
- **大数组慎用作 Vec 信号**：叶子展开是结构开销——千级元素的聚合状态应重新考虑是否该用 Mem；Vec 信号的定位是小规模聚合（总线、握手、多路端口）。
